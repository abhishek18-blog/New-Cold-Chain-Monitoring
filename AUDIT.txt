refactored from a heavy, legacy, local Apache Kafka cluster into a streamlined,

----------------------------------
1. Message Broker:
   - BEFORE: 3 dedicated VMs running Apache Kafka (KRaft mode), requiring manual 
     partition rebalancing, disk management, and persistent idle compute charges.

     automatically from 0 to 1,000,000+ msgs/sec with zero idle infrastructure cost.

2. Analytical Ingestion:
   - BEFORE: Custom intermediate Python bridge (`pubsub-bridge`) running 24/7.
   - AFTER: Direct BigQuery Streaming Subscription (`telemetry-bigquery-sub`) 
     writing raw native JSON directly to BigQuery with ZERO consumer code.

   - BEFORE: Fast2SMS API gateway (locked out with HTTP 400 status 999 due to 
     TRAI KYC regulations and payment gateway restrictions).
   - AFTER: Decoupled Cloud Run event worker dispatching instant, rich diagnostic 
     push cards via Discord Webhook directly to drivers' mobile phones.

   - AFTER: BigQuery 30-day partition expiration policy + automated GCS archival 
     script (`scripts/archive_bigquery_to_gcs.py`) saving compressed `.jsonl.gz`.

5. Frontend Delivery Data Path:
   - BEFORE: Browser HTTP REST polling loops hitting `dashboard-api` every 1-2s.

     streaming sub-second map updates directly to browsers via WebSockets/gRPC.

[TIER 3: REAL-TIME STATE STORE (CLOUD FIRESTORE)]
- Status: VERIFIED & READY
- Mode: Native Mode (`(default)` database).
- Data Model & Ingress Protections:
  * Isolated Document Routing: Every truck writes to its own isolated document:
    `trucks/truck_{id}` and `live_status/{id}` (avoids global array lock contention).
  * Rate-Limit Protection: Normal simulator cadence runs at 1.0s interval to 
    strictly comply with Firestore's 1-write/sec/document quota.
  * Backlog Ingress Filter: Messages flagged with `is_backlog: "true"` are 
    preserved in BigQuery but completely bypass Firestore, preventing the 
    live dashboard map from jumping backwards.
  * Timestamp Guard: Out-of-order or duplicate telemetry packets 
    (`incoming_ts <= existing_last_ts`) are rejected from live state.
  * Audit Log Uniqueness: Every alert generates a cryptographically unique 
    document ID (`alert_{truck_id}_{timestamp}_{uuid}`) in `alerts` collection.

- Schema: Native `data JSON` column, preserving raw IoT attributes without schema breaks.
- Partitioning: Partitioned daily by `publish_time`, clustered by `truck_id`.

  * Cold Archive Bucket: `gs://${PROJECT_ID}-coldchain-archive-prod`.
  * Automated Exporter: `scripts/archive_bigquery_to_gcs.py` extracts cold partitions

================================================================================
The repository includes a turnkey 1-command deployment script: `terraform/deploy.sh`.

Prerequisites:
--------------
- Google Cloud Shell or local terminal authenticated with `gcloud auth login`.
- Active GCP Project with billing enabled.

Step-by-Step Deployment:
------------------------
1. Set the active GCP project:
   $ gcloud config set project <YOUR_PROJECT_ID>

2. Run the deployment script:
   $ chmod +x terraform/deploy.sh
   $ ./terraform/deploy.sh <YOUR_PROJECT_ID> [REGION]

Deployment Automation Workflow:
-------------------------------
1. Automatically enables all 10 required GCP APIs:
   - `artifactregistry.googleapis.com`
   - `cloudbuild.googleapis.com`
   - `storage.googleapis.com`
   - `run.googleapis.com`
   - `pubsub.googleapis.com`
   - `firestore.googleapis.com`
   - `bigquery.googleapis.com`
   - `cloudscheduler.googleapis.com`
   - `cloudresourcemanager.googleapis.com`
   - `iam.googleapis.com`
2. Creates Artifact Registry Docker repository `coldchain-containers`.
3. Grants required Cloud Build IAM permissions.
4. Builds and tags all 5 microservice containers via Google Cloud Build.
5. Safely imports existing Firestore and Artifact Registry instances into state.
6. Provisions all Pub/Sub topics, BigQuery tables, and Cloud Run services via Terraform.
7. Prints public HTTPS Dashboard URL and BigQuery table path.

Useful Post-Deployment Commands:
--------------------------------
- View live stream processor logs:
  $ gcloud run services logs read coldchain-processor --region=asia-south1 --tail=50

- Trigger on-demand fleet telemetry simulation on GCP:
  $ gcloud run jobs execute coldchain-telemetry-generator --region=asia-south1

- Run manual silence detection audit:
  $ gcloud run jobs execute coldchain-silence-detector --region=asia-south1

- Query live telemetry from BigQuery using Google SQL:
  $ bq query --use_legacy_sql=false \
    'SELECT STRING(data.truck_id) AS truck, FLOAT64(data.cargo_temp_c) AS temp, publish_time 
     FROM `coldchain_analytics.telemetry_stream` 
     ORDER BY publish_time DESC LIMIT 10'

- Teardown & destroy all GCP resources (stops all billing):
  $ cd terraform && terraform destroy -auto-approve
